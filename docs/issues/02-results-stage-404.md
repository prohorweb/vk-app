# results: привести 404 неопубликованного этапа к контракту

**Приоритет:** P0
**Endpoint:** `GET /api/v1/results/stage/{stage_id}`

## Сейчас

- В OpenAPI описаны только `200` и `422`.
- На живом API: этап 1 — `200`, `publication: provisional`; этапы 2 и 3 — `404`.
- Фронт трактует `404` как «протокола нет» и отбрасывает `draft`, но в консоли остаются
  ошибки на каждый неопубликованный этап.

## Нужно

Выбрать один вариант и зафиксировать его в контракте:

1. описать `404` для неопубликованного этапа в `responses`; или
2. всегда отдавать `200` с `publication: draft` для этапов сезона без результатов.

## Acceptance criteria

- [ ] В OpenAPI нет незадокументированных статусов.
- [ ] Экран «Результаты» не генерирует `404` в штатном сценарии.
- [ ] `openapi.json` обновлён.

## Контекст

- Фронт: `fetchStageProtocol` в `src/api/queries.ts`.
- Проверка 25.10.2026: `results/stage/1` → `200`, `results/stage/2` и `results/stage/3` → `404`.
