# viewer-locations: типы зон из макета «Карта зрительских локаций»

**Приоритет:** P1
**Endpoint:** `GET /api/v1/content/viewer-locations`
**Статус:** открыто. Фронт уже рисует метки-пины, но раскладка глифов и фильтры
ждут новых значений `ViewerLocationKind`.

## Зачем

Макет `docs/figma/Карта зрительских локаций/` (7 экранов) описывает площадки
фестиваля, а не точки трассы:

| Иконка в макете | Подпись на карте | Цвет кружка |
| --------------- | ---------------- | ----------- |
| микрофон        | Главная сцена    | `#1973B0`   |
| яблоко          | Фудкорт          | `#34C759`   |
| камера          | Фотозона         | `#FFCC00`   |
| пейзаж в рамке  | Этнозона         | `#00C0E8`   |
| смайлик         | Детская зона     | `#CB30E0`   |
| огонь           | Шатёр            | `#AC7F5E`   |

Тулбар в этих же макетах: «Все · Детям · Еда · Сцены · Площадки» — то есть фильтр
идёт по назначению зоны, а не по роли точки в гонке.

Сейчас контракт отдаёт `start | finish | festival | viewpoint | other`, в demo seed
четыре точки (старт, финиш, смотровая, фестивальная площадка). Ни одна из шести зон
макета в эту схему не ложится, поэтому фронт вынужден угадывать глиф по типу, а
подписи чипов («Старт / Финиш / Смотровые / Фестиваль») расходятся с макетом.

## Что сделать

1. Расширить `ViewerLocationKind` (`app/enums.py`) значениями зон:
   `kids`, `food`, `stage`, `tent`, `photo`, `ethno`.
   Старые значения (`start`, `finish`, `viewpoint`, `festival`, `other`) оставить:
   на них завязаны зрительские точки вдоль трассы и fallback-моки фронта.
2. В demo seed (`scripts/seed_mock.py`, `VIEWER_LOCATIONS`) положить шесть зон
   макета: название, `kind`, координаты в Петропавловске-Камчатском (центр,
   `53.02–53.10 / 158.60–158.68`), `facilities`, `travel_time_minutes`, `address`.
   Сейчас координаты генерируются случайно (`_random_position`) — для зон нужны
   фиксированные точки, иначе метки «прыгают» между сидами.
3. `km_from_race_start` и `first_arrival_planned_at` у зон не нужны: оставить `null`,
   у зон нет километража и времени приезда участников.
4. Обновить `openapi.json` (`scripts/export_openapi.py`), фронт регенерирует
   `src/api/schema.d.ts` (`npm run gen:api`).
5. Сбросить кэш `public:content:*` после пере-сида.

## Как это использует фронт

- Глифы уже заведены: `src/map/placemarkPins.ts` (`PLACEMARK_GLYPH_BY_KIND`).
  После регенерации схемы добавим соответствие 1:1 для новых `kind`.
- Чипы тулбара будут собираться из `kind`: «Все», «Детям» (`kids`), «Еда» (`food`),
  «Сцены» (`stage`), «Площадки» (`tent` + `photo` + `ethno` — одна группа).
- Порядок чипов задаёт фронт, бэкенд отдаёт только `kind`.

## Acceptance criteria

```bash
curl -s 'http://127.0.0.1:8000/api/v1/content/viewer-locations?limit=100' \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print([(i['name'], i['kind']) for i in d['items']])"
# 6 зон: Главная сцена/stage, Фудкорт/food, Фотозона/photo, Этнозона/ethno,
#         Детская зона/kids, Шатёр/tent
```

- [ ] `ViewerLocationKind` содержит `kids`, `food`, `stage`, `tent`, `photo`, `ethno`.
- [ ] Demo seed даёт шесть зон с фиксированными координатами.
- [ ] `openapi.json` обновлён, `ViewerLocationKind` в схеме содержит новые значения.
- [ ] Старые `start/finish/viewpoint/festival/other` продолжают отдаваться.

## Заметки

- Тулбар уже показывает чипы макета: «Площадки» — старые `kind`, а «Детям», «Еда»,
  «Сцены» пусты до появления новых значений (экран пишет «Площадок пока нет»).
- Пока issue не закрыт, фронт рисует пины по старой пятёрке: `start` → огонь,
  `finish` → камера, `viewpoint` → пейзаж, `festival` → микрофон, `other` → яблоко.
  Это временное сопоставление, менять его нужно вместе с контрактом.
- Смайлик (детская зона) на карте пока не используется — нет `kind`.
